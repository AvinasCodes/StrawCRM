STRAWCRM BACKEND SCHEMA
========================

STACK
-----
Backend: Python + FastAPI
Database: Google Cloud Firestore (Real-Time Document Store)
File Storage: FastAPI Local / Render Persistent Uploads (/uploads/)
AI: Gemini API
Hosting: Render / Railway

DATABASE (FIRESTORE COLLECTIONS)
--------------------------------
COLLECTION: tickets

id              Document ID (e.g., TKT-001)
ticket_id       STRING UNIQUE NOT NULL (e.g., 'TKT-001')
customer_name   STRING NOT NULL
customer_email  STRING NOT NULL
subject         STRING NOT NULL
description     STRING NOT NULL
status          STRING NOT NULL DEFAULT 'Open'
attachments     ARRAY OF OBJECTS (name, size, type, url, created_at)
created_at      ISO 8601 TIMESTAMP NOT NULL
updated_at      ISO 8601 TIMESTAMP NOT NULL

Allowed status:
Open
In Progress
Closed


SUBCOLLECTION: tickets/{ticket_id}/notes

id              Document ID (e.g., note_1789008756)
ticket_id       STRING NOT NULL
note_text       STRING NOT NULL
author_name     STRING (e.g., 'Aaryan Singh')
author_email    STRING (e.g., 'admin@datastraw.in')
created_at      ISO 8601 TIMESTAMP NOT NULL

Relationship:
tickets (1) : (N) tickets/{ticket_id}/notes


SQL EQUIVALENT SCHEMA (FOR SPEC PARITY)
---------------------------------------

CREATE TABLE tickets (
    id BIGSERIAL PRIMARY KEY,
    ticket_id VARCHAR(20) UNIQUE NOT NULL,
    customer_name VARCHAR(150) NOT NULL,
    customer_email VARCHAR(255) NOT NULL,
    subject VARCHAR(255) NOT NULL,
    description TEXT NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'Open',
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT tickets_status_check
        CHECK (status IN ('Open', 'In Progress', 'Closed'))
);

CREATE TABLE notes (
    id BIGSERIAL PRIMARY KEY,
    ticket_id VARCHAR(20) NOT NULL,
    note_text TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT notes_ticket_fk
        FOREIGN KEY (ticket_id)
        REFERENCES tickets(ticket_id)
        ON DELETE CASCADE
);

REST API
--------

POST /api/tickets
Create a ticket.

GET /api/tickets
List all tickets.

GET /api/tickets?search=rahul
Search tickets by ticket ID, customer name, email, subject, or description.

GET /api/tickets?status=Open
Filter tickets by status.

GET /api/tickets?status=Open&search=rahul
Search and filter together.

GET /api/tickets/{ticket_id}
Get ticket details and notes.

PUT /api/tickets/{ticket_id}
Update ticket status and optionally add a note.

POST /api/upload
Upload a ticket attachment (images, logs, documents up to 50MB) and receive a static hosted URL.

GET /api/dashboard/summary
Get operational metrics, KPI counts, and recent tickets.

GET /api/analytics/overview
Get aggregated support metrics and resolution statistics.

VALIDATION
----------

- Customer name required
- Valid email required
- Subject required
- Description required
- Status must be Open, In Progress, or Closed
- Ticket ID must exist before update
- Notes cannot be empty
- Ticket ID must be unique
- New tickets default to Open
- Timestamps generated automatically
- File upload enforced up to 50 MB with sanitized filenames
